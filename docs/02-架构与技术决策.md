# 02 · 架构与技术决策

## 技术选型与理由

| 选择 | 理由 |
|---|---|
| FastAPI + uvicorn | 单文件可运行、异步流式转发顺手、自带 OpenAPI |
| SQLite（WAL） | 零部署；WAL 支持交接期新旧进程同时写 |
| JSON 配置（`data/config.json`） | 人可读、可备份、可手工编辑；pydantic 模型校验 |
| 原生 HTML/CSS/JS 前端 | **无构建链**，改完刷新即生效，不需 Node 工具链 |
| PyInstaller（可选） | `scripts/build_exe.py` 打包单 exe，"拷贝即用" |

## 模块地图

```
run.py                    启动入口：解析 --host/--port/--no-browser，uvicorn.run
backend/
  main.py                 FastAPI 应用、CORS、lifespan（健康检查循环）、
                          /healthz、静态站点挂载、runtime_addr（实际监听地址）
  proxy_routes.py         代理入口 /v1/messages、/v1/chat/completions
  converter.py            Anthropic ⇄ OpenAI 双向转换（含流式 SSE）
  upstream_pool.py        候选上游选取、请求转发、失败计数/冷却、健康检查
  admin_routes.py         /api/* 管理接口 + /api/server/restart 端口交接
  config.py               Settings/Upstream/ModelMapping/ClientKey 模型 + JSON 持久化
  database.py             SQLite 日志写入、概览统计、5h/7d/30d 用量窗口
  limiter.py              客户端 Key 的滑动窗口 RPM 与每日 Token 限额
  paths.py                数据/资源目录解析（兼容源码运行与 PyInstaller _MEIPASS）
web/                      index.html + app.js + style.css（无构建）
scripts/
  service.py              状态查询 / 停止 / 开机自启（计划任务 Switchboard）
  import_opencode_go.py   一键导入 OpenCode Go 上游与映射
  build_exe.py            打包 exe 到 release/
tests/                    自包含脚本：直接 python tests/xxx.py 运行，无 pytest 依赖
```

## 两条请求链路

**管理面**：浏览器 → `/`（静态站点）→ `fetch /api/*` → `admin_routes.py` → `config.py` /
`database.py`。鉴权：设置管理口令后要求 `X-Admin-Token` 头。

**代理面**：Claude Code → `POST /v1/messages`（或 `/v1/chat/completions`）→

1. 客户端 Key 鉴权（`config.py` 存储的 Key 表，`sk-px-` 前缀约定）
2. `limiter.py` 限流检查（RPM / 每日 Token）
3. `config.py` 映射解析：请求模型名 → 别名匹配 → 得到目标模型与（可选）绑定上游
4. `upstream_pool.py` 选上游：按请求模型过滤 `models` 白名单 → priority/weight 排序
5. `converter.py` 按需转换（客户端协议 × 上游协议）
6. 转发（流式则 SSE 透传转换）、失败计数/冷却、按 `max_retries` 换下一个候选
7. `database.py` 落日志（模型、Token、延迟、成败、上游）

## 数据模型（`data/config.json`）

| 实体 | 关键字段 |
|---|---|
| Settings | host, port, admin_token, log_retention_days, enable_log, request_timeout, cooldown_seconds, failure_threshold, health_check_interval, health_check_enabled, auto_open_browser, use_system_proxy |
| Upstream | id, name, base_url, api_key, protocol(`anthropic`\|`openai`), enabled, priority, weight, timeout, max_retries, models[], note（运行态字段 healthy/cooldown_until/… 由 `runtime_state()` 追加，不落盘） |
| ModelMapping | id, alias, target, upstream_id(空=自动调度), enabled, note |
| ClientKey | id, name, key, enabled, rate_limit_rpm, daily_token_limit, allowed_models[], upstream_id, note |

请求日志在 `data/proxy.db`（SQLite WAL：`proxy.db-wal/-shm`），仅元数据，按
`log_retention_days`（0=永久）清理。

## 配置生效语义

| 改动 | 生效方式 |
|---|---|
| 上游/映射/Key 增删改 | 保存即生效（下次请求读取） |
| 除 host/port 外的 Settings | 保存即生效 |
| **host / port** | 只能走 `POST /api/server/restart` 交接，见 [06](06-PRD-监听地址热更新.md) |
| 配置导入 | 覆盖上游/映射/Key；**不含** host/port 与 admin_token |

## 测试策略

- 全部为**自包含脚本**（内置 `check()` 断言、无需 pytest）：`python tests/test_xxx.py`
- `test_converter.py` 38 条：协议转换与流式事件映射
- `test_usage.py` 22 条：用量窗口边界（临时 SQLite）
- `test_frontend_contract.py` 60 条：HTML id ↔ JS 引用 ↔ 后端 API 三方对齐
- `test_e2e.py` 44 条 + `mock_upstream.py`：**清场会删光目标实例全部上游/映射/Key，
  必须用 `SWITCHBOARD_DATA_DIR` + 独立端口起隔离实例再跑（旧名 `CCP_DATA_DIR` 仍兼容）**（详见 03 文档）
- 本机注意：机器全局 `HTTP_PROXY=127.0.0.1:58889`，一切访问本机的 HTTP 客户端必须
  绕过代理（httpx 用 `trust_env=False`，urllib 用 `ProxyHandler({})`）
