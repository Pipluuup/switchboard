# 01 · 产品总览与路线

## 定位

带 Web 管理界面的**本地中转网关**，为 WorkBuddy、Claude Code 等 Agent 客户端打造：
把只讲 Anthropic 协议的客户端桥接到任意 OpenAI 兼容或 Anthropic 兼容的上游中转服务，
并提供多上游调度、模型映射、密钥分发、限流与用量统计。

一句话：**Agent 客户端不用改任何配置习惯，后端想用哪家就接哪家。**

> 命名：项目原名 CommandCode Proxy，2026-10-14 改名 **Switchboard**（接线总机，
> 取"多上游调度转接"之意），弱化对单一上游服务的绑定。

## 目标用户与核心场景

| # | 场景 | 价值 |
|---|---|---|
| S0 | **WorkBuddy 接入**：发一段接入提示词，Agent 自行完成配置 + 自测连通 | 零手工配置，接入指南内置在控制台 |
| S1 | Claude Code CLI → CommandCode（Goat 套餐）等 Anthropic 上游 | 直连中转，配置全图形化 |
| S2 | Claude Code CLI → GLM/Kimi/DeepSeek 等 OpenAI 格式服务 | 协议自动互转，工具调用完整可用 |
| S3 | 团队/多设备共用一套上游 | 每人发独立 Key，可单独限速/限模型/随时停用 |
| S4 | 盯紧上游额度 | 5h/7d/30d 滚动窗口用量，对齐 OpenCode Go 配额周期 |

## 非目标（明确不做）

- 不做多租户/公网部署：默认 `127.0.0.1`，管理面无强制鉴权（可设口令）。
- 不做请求内容的存储/审计：日志只记元数据（模型、Token、延迟、成败）。
- 不做 OpenAI `/v1/responses` 协议（见已知问题 #3）。

## 变更记录

### 2026-10-14

- **项目改名 Switchboard**（原 CommandCode Proxy）：`APP_NAME`、计划任务名、
  exe 名（`Switchboard.exe`，`build_exe.py` 的 `NAME`）、上游 UA（`Switchboard/1.0`）、
  `/v1/models` 的 `owned_by`、前端包名与页面标题均同步；数据目录环境变量改为
  `SWITCHBOARD_DATA_DIR`（旧名 `CCP_DATA_DIR` 仍兼容，见 `backend/paths.py`）。
  注意：已注册的旧名计划任务需用 `scripts/service.py` 重新注册。
- **定位调整**：README 与文档改为 WorkBuddy / Claude Code 优先的表述，
  CommandCode 从"项目本体"降级为上游示例之一。
- **前端品牌**：侧栏品牌 `P / Proxy` 改为 `S / Switchboard`，页面标题
  「Switchboard · 中转网关控制台」。

### 2026-10-13

- **免费节点体系**：上游名/备注含 `free` 即判定为免费节点——列表置顶 + 🎁 图标 +
  删除按钮禁用（内置不可删）；上游管理加「全部 / Free / 自定义」筛选。
- **新接入 3 个上游**（均为 OpenAI 协议、priority 300 兜底档）：
  - `Agnes AI (free)`（api.agnes-ai.cn）：文本模型 5 个入白名单；注意免费体验金

  - `SenseNova (free)`（token.sensenova.cn）：全 0 计费，白名单 5 个
    （glm-5.2 / kimi-k3 / deepseek-v4-flash / sensenova-6.8-flash-lite / deepseek-flash），
    免费档 tpm/rpm 限流较紧。
  - `Deepseek`（api.deepseek.com/anthropic，Anthropic 协议供 Claude Code 直连）；
    其 anthropic 端点无 /models，模型探测已做去尾兜底。
- **模型探测流程**：`POST /api/upstreams/probe-models`（新建未保存也可探测，Key 留空用已存值）；
  获取结果先进预选面板（默认全选 + 过滤 + 勾选），确认才写入。
- **Bug 修复**：编辑上游保存时不再覆盖留空的 API Key（此前会清掉已存 Key 导致
  `Illegal header value b'Bearer '`）。
- **OpenCode Go 白名单刷新**：以 `/v1/models` 实测为准扩到 33 个（新增 glm-5.1、

  `space-bunny-free` 已改名 `space-bunny`）。
- **模型映射**：目标模型改为联动下拉（先选上游，候选即其白名单；自动调度时取合集）；
  映射精简为单条 `Free → agnes-2.5-flash`（默认直通）。
- **接入指南**：新增「WorkBuddy 等 Agent 接入提示词」（发一段话让 Agent 自行配置 +
  自测连通）。
- **设置页**：两张配额卡片合并为「Plan 实时查询（配额官方数据）」，带「展开配置」
  勾选框（默认收起）与「展示用量」开关（控制用量页配额卡片显隐，存 `show_plan_usage`）。
- **前端**：概览两图表重写为 HTML 排版（修复 SVG viewBox 拉伸文字）；侧栏品牌改为

## 路线建议（按性价比排序）

1. **请求头透传**（修 #1）：`endpoint()` 增加 `extra_headers` 参数，上游表加自定义头字段——
   同时解决 Go 的 UA 要求与各家"必须带特定头"的通用问题。
2. **白名单落空直接 422**（修 #2）：明确告诉客户端"本网关无此模型"，别再扔给错误上游。
3. **`/v1/responses` 支持**（修 #3）：工作量大（新协议转换器 + 新入口路由 + 新上游协议类型），
   建议先只做透传模式（不转换、原样转发），覆盖 Grok/GPT Luna。
4. **用量窗口落库聚合**（修 #5）：新增按小时的聚合表，30d 窗口不再受日志保留期约束。
