# 01 · 产品总览与路线

## 定位

带 Web 管理界面的**本地中转网关**，为 WorkBuddy、Claude Code 等 Agent 客户端打造：
把只讲 Anthropic 协议的客户端桥接到任意 OpenAI 兼容或 Anthropic 兼容的上游中转服务，
并提供多上游调度、模型映射、密钥分发、限流与用量统计。

一句话：**Agent 客户端不用改任何配置习惯，后端想用哪家就接哪家。**

> 命名：项目原名 CommandCode Proxy，2026-10-14 改名 **Switchboard**（接线总机，
> 取"多上游调度转接"之意），弱化对单一上游服务的绑定。

## 目标用户与核心场景

| # | 场景 | 价值 |
|---|---|---|
| S0 | **WorkBuddy 接入**：发一段接入提示词，Agent 自行完成配置 + 自测连通 | 零手工配置，接入指南内置在控制台 |
| S1 | Claude Code CLI → CommandCode（Goat 套餐）等 Anthropic 上游 | 直连中转，配置全图形化 |
| S2 | Claude Code CLI → GLM/Kimi/DeepSeek 等 OpenAI 格式服务 | 协议自动互转，工具调用完整可用 |
| S3 | 团队/多设备共用一套上游 | 每人发独立 Key，可单独限速/限模型/随时停用 |
| S4 | 盯紧上游额度 | 5h/7d/30d 滚动窗口用量，对齐 OpenCode Go 配额周期 |
| S5 | **省 token 成本**：上下文越滚越长，压缩旧消息又不伤代码 | 网关侧压缩 + 缓存感知，日志逐条展示省了多少 |

## 非目标（明确不做）

- 不做多租户/公网部署：默认 `127.0.0.1`，管理面无强制鉴权（可设口令）。
- 不做请求内容的存储/审计：日志只记元数据（模型、Token、延迟、成败）。
- 不做 OpenAI `/v1/responses` 协议 → **已支持**（2026-10-21，见已知问题 #3）。

## 变更记录

### 2026-10-24

- **账号池**（路由组新子页，参考 CC-Switch v4 的账号池交互）：
  同一家上游服务的多枚账号（WorkBuddy 等「登录即授权」的 Cookie 型、
  或同型服务的多 Key）放进一个池，请求时**顺序轮换**——优先第一个
  启用且额度未尽的账号；账号级 401/403 自动停用该账号、下一次请求
  自动轮到下一枚。账号失败单独记账（failed_requests / last_error），
  不与上游熔断器互相干扰。
  - 创建池时**同步自动建一个同名池组上游节点**，note 以
    `account-pool:<pool_id>` 弱引用打标（不动 Upstream schema）；
    上游管理页对这类节点显示金色 `TeamOutlined`「池组」徽章。
    删池保留节点，改名/改地址后节点自动对齐。
  - 管理端点：GET/POST `/api/pools`、PUT/DELETE `/api/pools/{pid}`、
    POST `/api/pools/{pid}/probe`（逐账号用自身凭证请求 /models 探活）。
  - 前端新视图「账号池」：池卡（类型/协议/可用数徽章）+ 账号行
    （启用开关 / 额度条 / 最近使用 / 失败与最近错误 / 探活结果 tag）+
    「添加另一个账号」；与池绑定的池组节点可一键跳转上游管理。
  - 测试：`test_pools.py` 18 条（顺序轮换 / 额度用尽换号 / 401 自动停用 /
    池组节点绑定），`test_frontend_contract.py` 34 条全绿。

- **设置页排版收紧**：原「服务设置 / 调度与容错」两卡内容严重失衡
  （4 项 vs 熔断器 8 项），左列下方大片空白。重组为
  「服务与调度」（地址/端口/口令/超时/健康检查/失败阈值/冷却，数值项两列并排）、
  「熔断器」（独立卡，参数两列并排）两卡；「日志」数值项并排，
  「配置备份」改为小尺寸按钮。页面高度约 1400 → 1120px，字段与逻辑零改动。
- **映射 / 日志前端落地**（故障转移链的另一半）：
  - 映射编辑器：`Form.List` 渲染固定 3 档（编辑老式单档映射自动补足空位），
    每档 = 上游 Select + 模型 AutoComplete 并排；保存时剔除全空档、
    第 1 档镜像进 `target`/`upstream_id`。
    （踩坑：antd 5 `Space.Compact` + `Form.Item noStyle` 下 AutoComplete
    有值时宽度塌到 24px——放弃 Compact 改普通 flex 行。）
  - 映射表格：「目标模型」与「固定上游」两列合并为「故障转移链」单列逐档展示。
  - 日志页：新「切换」列（切换 N 次橙色 tag，悬停看各档摘要）、
    详情弹窗「切换轨迹」区（档号 / 模型 / 上游 / 状态着色 / 结果说明）。
- **故障转移链**：映射编辑器把「固定上游 + 目标模型」合成一档，可配 3 档
  从上到下依次尝试——上一档 5xx / 429 / 404 / 网络错误就切下一档
  （400/401 是请求本身的错，不切）。每档可留空上游（自动调度）或模型
  （沿用原模型名）。老映射（单档）零迁移继续工作。
  请求日志新增 `failover_trail`：一条日志内记下每次切档的
  档号 / 上游 / 模型 / 状态，日志页显示「切换 N 次」tag，详情弹窗画切换轨迹。
  测试：`test_failover_chain.py` 40 条 + `e2e_failover.py`（隔离实例）。
  详见 [03](03-PRD-代理核心与上游调度.md) 第 1 节。

### 2026-10-22

- **熔断器**：上游异常时自动拉黑，不再让每个请求都去撞一次。
  三态状态机（closed / open / half_open）+ 错误率阈值 + 半开探测。
  修掉了二元冷却的两个硬伤：抖动型上游（失败/成功交替）因为成功会清零计数
  而永远打不中阈值；冷却期结束是全量放行，上游没恢复就形成周期性雪崩。
  **错误按状态码分类**——客户端自己的 400/404/422 不再算上游的失败
  （旧实现连发 3 个格式错误的请求就能误熔断健康上游），401/403 则立即拉黑。
  设置页可调 7 个参数。
- **日聚合表**：30 天用量窗口不再被日志保留期截断（已知问题 #5）。
  新增 `usage_daily_rollups`，把明细按「天 × 上游 × 实际模型」压成一行；
  窗口长于保留期时改查它。写入走「按日期删除后重算」所以是幂等的。
- **缓存 token 落库**：以前 `extract_usage` 只取 `input_tokens`/`output_tokens`，
  缓存字段全被丢弃——用户看不到自己省了多少。现在按协议解析并统一口径
  （`input_tokens` 一律不含缓存），日志与用量页都显示缓存命中量。
  这个差异是真实的：Anthropic 的 `input_tokens` 不含缓存，
  OpenAI 的 `prompt_tokens` 含缓存。
- **静态资源畸形路径加固**：`/foo|bar`、`/x*y`、含 NUL 字节等畸形 URL 会让
  Windows 的 `os.stat`（WinError 123）/ `os.path.realpath`（ValueError）抛异常，
  2026-10-21 曾把整个服务进程带崩。`backend/main.py` 的 `_RobustStaticFiles`
  现在把这两类异常统一兜底为 404，垃圾路径只影响那一个请求。
  已在 `test_e2e.py` 加回归用例（第 15 节）。
- **e2e 测试地址可配**：`test_e2e.py` / `e2e_voice.py` 原先硬编码端口，跑隔离实例
  要手改源码。现在统一支持 `SWITCHBOARD_BASE` / `SWITCHBOARD_MOCK` 环境变量，
  CI 里两个 e2e 各用独立端口 + 独立数据目录，互不干扰。`e2e_voice.py` 已补进 CI。
- **OpenCode Go 导入脚本补上 Responses 上游**：脚本原先只建 Chat / Messages 两条，
  并打印「本代理没有 /v1/responses 路由」——但 Responses 协议 2026-10-21 就实现了。
  现在建第三条上游（`responses` 协议，base_url `https://opencode.ai/inference/go/v1`，
  白名单 6 个 Grok / GPT Luna / Muse Spark 模型）。Go 的 Grok 系列从「接不进来」
  变成「转换器就位、待实测连通性」。
- **文档纠偏**：docs/04 / docs/06 还在指已删除的 `web/app.js`（React 迁移前的旧文件），
  已改指 `frontend/src/views/Usage.tsx` / `Settings.tsx`；docs/05 的白名单数量、
  别名清单、「两条上游」等表述与代码脱节，已按 `import_opencode_go.py` 实际行为校正。
